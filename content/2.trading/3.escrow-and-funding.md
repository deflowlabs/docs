# Escrow and Funding

Every deal on DeFlow settles through a dedicated smart contract escrow. This page explains how the escrow system works, how funds are deposited and protected, and what happens in the event of cancellation or expiry.

## Non-Custodial by Design

DeFlow never holds user funds. When a deal is deployed, a new escrow contract instance is created on-chain. This contract is the sole custodian of the deal's assets until settlement. The platform cannot access, redirect, or withdraw funds from an active escrow.

## How Escrow Works

### Contract Deployment

When the deal creator deploys the escrow, the following occurs:

1. The **EscrowFactory** contract creates a new escrow instance using an EIP-1167 minimal proxy pattern
2. The escrow address is computed deterministically using CREATE2, meaning it can be verified before deployment
3. The deal terms (asset pair, amounts, expiry window, dispute window) are encoded into the escrow contract
4. The escrow is **immutable** once deployed. Its parameters cannot be changed by any party, including the platform

::callout{type="note"}
The deterministic address generation ensures transparency. Both parties can independently compute and verify the escrow address before depositing any funds.
::

### The EscrowFactory

The EscrowFactory is a single, audited contract that produces all escrow instances on the platform. Key properties:

| Property | Description |
|----------|-------------|
| **Deployment pattern** | EIP-1167 minimal proxy (gas-efficient cloning) |
| **Address generation** | CREATE2 (deterministic, pre-computable) |
| **Immutable instances** | Once deployed, individual escrows cannot be upgraded |
| **Governance** | Only the Factory itself is upgradeable, via multisig governance |

## The Funding Process

After the escrow is deployed, both parties fund their respective sides:

::step-guide

:::step{title="AML Pre-Check" n="1"}
Before each funding transaction, the platform verifies that the funding party's AML screening is current (within 24 hours). If the screening has expired, a new check is triggered automatically. Funding is blocked until the check passes.
:::

:::step{title="Wallet Screening" n="2"}
The funding wallet address is screened against international sanctions databases (OFAC, EU, UN, and others) via the Scorechain integration. If the wallet is flagged, funding is rejected and the user is notified.
:::

:::step{title="Deposit to Escrow" n="3"}
The user sends a transaction depositing the full amount of their side of the deal into the escrow contract. Partial deposits are not accepted. The transaction must transfer the exact amount specified in the deal terms.
:::

:::step{title="On-Chain Confirmation" n="4"}
The escrow contract emits a **Funded** event when the deposit is confirmed on-chain. The platform indexes this event and updates the deal status. Both parties can see the funding status in real time on the deal detail page.
:::

::

## Funding Rules

| Rule | Detail |
|------|--------|
| **Full amount required** | Each party must deposit the exact amount specified. No partial funding |
| **Order independent** | Either party can fund first. There is no required sequence |
| **Single transaction** | Each side is funded in a single transaction |
| **Expiry enforcement** | If both sides are not funded before the expiry window elapses, the deal is cancelled |
| **Compliance gating** | AML screening and wallet screening must pass before each deposit |

## What Happens to Your Funds

Once deposited, your funds are held in the escrow contract until one of the following outcomes:

| Outcome | What happens to funds |
|---------|----------------------|
| **Settlement** | Both sides receive the counterparty's assets. Fees are routed to the FeeRouter contract |
| **Cancellation** | All deposited funds are returned to the original depositors |
| **Expiry** | The deal expires and the escrow automatically refunds all deposits |
| **Dispute** | Funds remain locked until the dispute is resolved by mutual agreement or governance |

::callout{type="tip"}
You can verify the state of your funds at any time by inspecting the escrow contract directly on a block explorer. The contract address is displayed on the deal detail page.
::

## Fee Routing

At settlement, fees are calculated and routed through the **FeeRouter** contract:

1. The base platform fee (typically 0.50%) is applied to the deal's notional value
2. Any VIP tier discount reduces the fee
3. Any referral credits are applied (up to 50% off the remaining fee)
4. The net fee is split on-chain between the platform treasury and, if applicable, the introducing broker or desk

All fee calculations are transparent and visible to both parties before settlement.

## Payout Isolation

Settlement is designed with payout isolation. If a secondary payout (such as a broker commission) fails due to a smart contract issue, the core settlement between the two deal parties still completes. Failed secondary payouts are captured in the event index for administrative retry. This ensures that core deal execution is never blocked by ancillary payment failures.
