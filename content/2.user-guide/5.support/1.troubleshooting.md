## Wallet is on the wrong network

Switch to Ethereum Sepolia and confirm chain ID `11155111`. Reject any request to use mainnet or an unrecognised network. If a transaction was already submitted elsewhere, do not repeat it until support has reviewed the public hash.

## Transaction is pending

Check the public Sepolia receipt and wallet gas settings. Testnet confirmation can be slow. Do not submit repeated deposits or settlements simply because the application has not refreshed.

## Transaction succeeded but the page is stale

Wait for the confirmation window, refresh once, and compare the deal state with the Sepolia receipt. Capture the deal ID, contract address, transaction hash, and visible status for support.

## Identity status does not update

Return from the provider window, allow the status page to refresh, and avoid opening multiple verification sessions. Do not email documents or provider screenshots containing sensitive identity details.

## TestUSDC is missing

Confirm the token address is `0x0F5D9F6546aa791De4B9543d57f8C19b668Eb10E`. Tokens with the same symbol at another address are not supported by the current deployment.

## Syndicate draft or allocation does not advance

Do not recreate or resubmit the action repeatedly. The Syndicate flow is in supervised integration validation. Record the Syndicate ID, allocation ID if present, current status, requested or approved amount, exact error and time. If an on-chain action occurred, also record the escrow address and transaction hash, then contact support.

## Syndicate funded progress looks wrong

Treat the allocation record and Sepolia receipt as the primary evidence. The aggregate progress display is still being validated. Do not send another deposit to make the visual total change.

## Suspected security issue

Stop interacting with the affected workflow and contact [security@deflowlabs.io](mailto:security@deflowlabs.io) privately. Never share secrets when reporting an issue.
